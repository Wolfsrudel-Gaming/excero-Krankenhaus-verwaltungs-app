# v1.9 – Das Produktreif-Update (Plan aus der Anforderungs-Befragung)

Ziel: Mehrbenutzer-Betrieb mit 2–3 Geräten ab kommender Woche, real abrechenbar.
Umfang: ALLES in einem Update (Wunsch des Nutzers). App-Repo = App; Web = Cursor
(Sync-API-Änderungen hier additiv umsetzen und in server/ mitliefern + SYNC-API.md).

## Mehrbenutzer (Kern)
- Gerät = Mitarbeiter: Name wird einmalig fest im Gerät hinterlegt (Einstellungen).
  Mitarbeiterliste wird im WEB verwaltet (anlegen/deaktivieren); App zieht die Liste
  beim Sync und bietet sie bei der Erstwahl an. Keine Passwörter, alle sehen alles.
- Inspection bekommt Feld `mitarbeiter` (Migration v8); erscheint auf Prüfbogen-UI,
  PDF, Web, Excel („Geprüft von").
- Sync-Erweiterung: Prüfbögen/Berichte ALLER Mitarbeiter werden auf jedes Gerät
  gepullt (GET /api/sync/inspections), Fotos NICHT (bleiben serverseitig; App zeigt
  bei fremden Berichten „Fotos auf dem Server").
- Sync-Takt: so schnell wie möglich → Foreground-Polling alle 60–120 s solange App
  offen + nach jedem Speichern + beim Start (kein Websocket-Overkill, aber gefühlt live).
- Live/Team: Zimmerübersicht zählt Team-Fortschritt gesamt; am Zimmer Badge wer
  geprüft hat; „heute von Kollege X geprüft" verhindert Doppelarbeit.
- Offline bleibt voll erhalten (lokal speichern, nachsyncen).

## Stundenzettel im Team (Abrechnung)
- EIN Zettel pro Station/Zeitraum, mehrere Mitarbeiter darauf: je MA eine Zeile
  mit Arbeitsstunden + Anfahrt, plus Gesamtsumme. Neue Tabelle
  stundenzettel_eintraege (zettelId, mitarbeiter, stunden, anfahrt) + Migration.
- Unterschriften: Station + JEDER beteiligte MA (dynamische Felder,
  SignatureStore-Rollen "station", "ma_<name>").
- Zettel wird über den Server geteilt: MA B sieht/ergänzt den Zettel, den MA A
  angelegt hat (Sync der Einträge, LWW je Eintrag).
- Einsatz-Zeiterfassung: „Einsatz starten/beenden" je Station (Empfehlung
  angenommen) → befüllt die eigene Stundenzeile automatisch vor.
- PDF: Zeilen je MA + Summen + alle Unterschriften.

## Web (Cursor umsetzt; ich liefere Server-API in server/)
- Mitarbeiter-Verwaltung (CRUD) → GET/POST/PATCH /api/web/mitarbeiter
  + GET /api/sync/mitarbeiter für die App.
- Material & Bestände-Ansicht + Nachbestell-Warnliste (Endpunkte vorhanden).
- Stundenzettel-PDF im Web erzeugen/downloaden.
- Aktivität & Sperren live (Endpunkte vorhanden).
- Mehrere Web-Benutzer (Tabelle web_users) statt ein Admin-Passwort.
- Abrechnungsreport pro Monat/Zeitraum (Einsätze, Stunden je MA, Material) als
  PDF + Excel aus dem Web.
- Optik-Feinschliff wichtig (Chef-Demo!), auch mobil.

## App-Zusatzfeatures
- Freenet-Ablaufübersicht (stationsübergreifend, sortiert nach Ablauf).
- Interne Statistik-Seite (Prüfungen/Monat, n.i.O.-Quoten, Verlängerungen).
- Berichtssuche mit Filtern (Datum/Station/n.i.O.) + Papierkorb für Fotos/Berichte.
- KEIN OCR in 1.9.

- „Testdaten bereinigen"-Funktion (Einstellungen): löscht Prüfbögen/Fotos/Zettel,

## Nachtrag: Leistung & Auto-Updates (2. Befragungsrunde)

### Server-Power nutzen
- Delta-Sync: /api/sync/inspections|rooms|aktivitaet akzeptieren ?since=<ts>;
  App merkt sich lastSync und überträgt/holt nur Änderungen → skaliert auf Jahre.
- Thumbnails: Server erzeugt beim Upload automatisch Vorschaubilder (sharp),
  Web-Galerie lädt Thumbs statt Originale (schnell auch bei hunderten Fotos).
- Automatische Backups: Server sichert nächtlich pg_dump + Dateien als
  datiertes Archiv (30 Tage Rotation) in ein Volume – ohne Zutun.
- Indexe + Pagination auf allen Listen-Endpunkten.
- Abrechnungsreport (PDF/Excel) wird serverseitig erzeugt (pdfkit/exceljs).

### Automatische Updates
- Server-Autodeploy: systemd-Timer prüft alle 5 Min das Git-Remote;
  bei neuem Commit: git pull + docker compose up -d --build.
  → Jeder Push (von Claude oder Cursor) aktualisiert den Server von selbst.
- App-Updater: deploy legt die aktuelle APK + version.json unter
  /kkh/app ab; die App prüft beim Sync die Version, zeigt "Update verfügbar",
  lädt die APK und startet den Android-Installationsdialog
  (REQUEST_INSTALL_PACKAGES). Kollegen installieren einmalig per Link/QR,
  danach kommen Updates aus der App heraus.
